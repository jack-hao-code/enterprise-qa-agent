# 项目复盘

本节记录本版本实现中实际遇到的问题与取舍，不代替候选人本人应填写的学习经历。

## 最难的问题

可靠回答不仅是找到一段文字，还要避免把“找到了一条制度”误当成“已经排除了其他冲突制度”。实现将检索与原文读取分开，要求先核对候选，并对已标注的同范围矛盾阻止直接回答；版本日期只作为资料信息，不能自行决定优先级。

另一个边界是“引文存在”与“引文足以展示结论”的区别。测试发现冲突双方都引用相同的无关短词也可过基础校验，因此增加了冲突规定值必须出现在对应引文中的检查。正常回答采用原文抽取，减少额外事实，但语义相关性仍需模型与人工复核。

## 实际改进

资料外问题的回归失败揭示了补查泛词造成的误召回；上下文追问的批量评估又暴露了整段历史拼接带来的无关引用。两者都通过查看工具输入和实际返回定位，先保留失败测试，再修改离线替身的查询行为，没有调整预期状态来制造通过。

这些改进没有证明通用检索和对话理解已解决。尤其 Mock 的同义词和指代规则只是为可复现的流程测试服务，真实模型需要单独检验。

## 为什么控制范围

本题重点是模型观察工具结果后作出下一步选择、答案有原文依据、失败状态真实。因此优先实现两个业务工具、真实模型入口、有界循环、可核对 Trace 和验收回归。未增加 UI、部署、多 Agent 业务协作或向量数据库，避免这些工作挤占核心验证。

## 下一步优先级

1. 使用候选人选择的真实模型运行全部场景，保留至少两条动态路径并人工核对；这是当前最重要的证据缺口。
2. 加入更丰富的同义问题、含噪声历史、无结构化标注的冲突资料，区分检索失败和模型判断失败。
3. 扩展为中文分词或混合检索，并用固定评测集比较召回变化，避免仅在当前少量示例上优化。
4. 如实际业务需要，再设计制度适用范围、明确优先级和证据更新机制，而不是按日期简单覆盖。

## 时间与个人学习

本项目不编造候选人实际投入和学习收获。程序评估耗时在报告中；候选人应另行记录阅读、修改、调试与真实模型验证用时，并用自己的理解改写本节。
