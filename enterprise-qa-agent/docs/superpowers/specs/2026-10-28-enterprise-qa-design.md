# 企业知识问答 Agent 设计

沿用已向用户提出、用户要求完整交付的方案：Python CLI、合成 JSON 文档、关键词检索、真实模型工具调用；额外提供明确标注的离线 Mock。

目标：交付第三题的可运行代码、可执行验收、输入/实际输出/Trace、五份中文文档及提交说明。不代替用户填写个人经历，不伪造模型运行或 GitHub 地址。

备选：向量检索增加依赖与数据构建成本；Notebook 方便演示但不利于批量回归。选择标准库 CLI，便于评审离线复现。

模块：documents.py 校验合成资料与搜索/读取；protocol.py 定义工具协议；backends.py 提供 HTTP 模型适配与明确的规则 Mock；agent.py 执行有上限的观察循环及引用/冲突门禁；cli.py 负责参数与结果落盘；evaluate.py 批量运行六项验收及失败恢复等扩展用例。

每步由后端返回一个动作；执行结果以 tool 消息交回后端，由下一次决策决定动作。真实模式不引用 Mock 逻辑、不自动降级 Mock。Mock 仅演示控制流。

输出状态：answered / needs_clarification / no_answer / tool_error / incomplete。引用必须来自本次成功读取的原文。带 claim_key/claim_value 的人工合成片段支持保守冲突门禁；元数据不完整的自然语言矛盾仍依赖模型判断，文档明确局限。

测试覆盖六项必验、暂时失败恢复、持续失败、步数上限、伪造引用、冲突漏读、模型接口异常。保存模型名、模式、时间、数据摘要、动作参数、观察摘要、后续动作与公开简要依据；不保存内部思维过程或密钥。

没有用户提供的模型凭据，不进行付费外部调用；可交付真实模式入口及本地协议测试，但评估中必须写明真实模型证据尚缺。
