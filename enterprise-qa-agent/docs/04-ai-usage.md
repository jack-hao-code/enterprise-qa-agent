# AI 辅助使用与个人贡献

## 本交付版本的真实来源

本项目初版由 Codex 在用户提供的第三题要求下生成，包含架构建议、Python 代码、合成资料、自动测试、评估脚本、示例运行记录及文档。Codex 在本地执行测试和离线评估，检查失败并修改实现；另按代码评审流程进行独立审查。没有真实模型运行结果。

代码运行中的 `MockBackend` 与生成项目所使用的 Codex 是不同概念。Mock 是项目内的规则测试替身，它的动作日志不等于开发辅助模型的实际工具调用，也不等于真实业务模型决策证据。

## AI 辅助范围

| 内容 | 辅助情况 | 当前验证 |
|---|---|---|
| 需求分解、技术选择 | AI 提出标准库 CLI、两个只读工具和有界循环 | 与用户提供的验收项逐项对应 |
| 代码与测试初稿 | AI 生成并迭代 | 实际本地测试日志见 examples/mock/test-results.txt |
| 合成文档与场景 | AI 构造，不含真实企业资料 | 校验 ID、日期、片段和事实值 |
| 离线执行记录 | 程序实际运行产物 | 每组输出含输入、模式、数据摘要与完整 Trace |
| 文档与复盘初稿 | AI 根据实际实现和失败记录撰写 | 明确真实模型与个人贡献未核实部分 |
| 真实业务模型效果 | 未运行 | 不作通过声明 |

## 候选人个人贡献记录

本会话中候选人提供了考核说明并选择了第三题交付方向。候选人本人对代码的理解、手工修改、模型选择、真实运行与独立验证尚未由本项目确认，不能将 AI 完成的工作直接写为“本人独立实现”。

提交前请根据实际发生的工作补充：阅读和理解了哪些模块、亲自修改了哪些内容、修改原因、运行了哪些命令、发现了什么问题、真实模型的表现以及实际投入时间。没有做过的步骤应写未完成，不应虚构个人经历。

## 核实清单

- 能说明模型决定动作与执行器做安全/证据检查的职责边界。
- 能解释为何 Mock 无法代替模型 ReAct 证据。
- 能自行运行并解释六项验收及至少两条真实路径。
- 能通过修改 D01 内容观察答案变化，并说明仍存在的召回与冲突识别限制。
- 核对最终 GitHub 仓库、commit SHA 与本地已验证代码一致。
