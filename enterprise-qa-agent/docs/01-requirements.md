# 需求与成功标准

## 用户与业务目标

面向查询企业制度或产品信息的员工。输入问题和可选对话历史，查询带文档 ID、片段 ID 和版本日期的合成资料，提供可以逐字核对的依据。资料不够时指出缺口，制度冲突时请求明确适用范围或优先级。

## 范围

本项目提供 CLI、合成知识库、文档检索与读取工具、真实模型工具调用、离线 Mock、运行记录及自动评估。不接入真实企业资料，不配置网页界面、向量数据库、权限系统、发布动作或企业写入操作。

正常资料含费用报销期限、差旅住宿标准、远程办公和演示产品导出说明。冲突资料仅用于模拟同一事项不同规定。所有文本和日期为人工合成，不代表任何真实公司的制度。

## 验收映射

| 必验项 | 输入/资料 | 成功标准 | 实际证据 |
|---|---|---|---|
| 明确答案 | normal + documents | answered，引用 D01/C01，答案含30天 | [normal](../examples/mock/normal.json) |
| 文档冲突 | conflict + conflict | 读取 D01、D02；列出30天与15天，追问，不能选日期较新文档作为唯一答案 | [conflict](../examples/mock/conflict.json) |
| 资料外问题 | out_of_scope | 补查后 no_answer，给出缺口，无伪造引用 | [out_of_scope](../examples/mock/out_of_scope.json) |
| 改写后的相似问题 | paraphrase | 识别报销相关意图，补查后引用同一原文 | [paraphrase](../examples/mock/paraphrase.json) |
| 上下文追问 | followup | 利用历史识别话题，本次重新读取并引用原文 | [followup](../examples/mock/followup.json) |
| 工具失败 | normal + 读取持续失败 | tool_error，记录真实失败观察，不生成成功答案 | [tool_failure](../examples/mock/tool_failure.json) |

以上文件当前为 **Mock 的实际运行结果**，只证明离线流程和边界检查。真实模型的六项表现须通过 `python3 scripts/evaluate.py --backend live` 另行执行，不能由本表替代。

附加场景：首次失败后恢复、缺少问题、执行步数上限、资料从30天改为45天。分别验证错误观察后的后续动作、追问、明确未完成状态及答案随来源变化。

## 非功能与安全边界

- 默认最多10次模型决策，CLI 允许1-30次，每次最多执行一个动作，含 finish。
- 必须实际检索和读取后才能正常回答；引文必须来自本次读取的片段。
- 检索返回的候选应全部读取核对；截断结果须用同一查询扩大 limit 消除。上限20仍截断则请求缩小范围，不能用无关查询清除标记。
- 不凭版本日期自行确定制度优先级；标注范围相同且事实值不同的冲突由运行时阻断直接回答。
- 历史与原文为待核实的数据，不能新增系统角色或执行任意工具。
- 真实模式失败明确报告，禁止悄悄改用 Mock。
- 不记录密钥、模型内部思维过程或外部接口完整错误响应体。

## 用时记录

自动评估实际运行耗时在 [report.json](../examples/mock/report.json) 的 `duration_seconds` 字段。该数值仅是程序运行耗时。候选人本人投入、学习与修改时间尚未提供，不在本项目中编造；提交前应据实补充。
